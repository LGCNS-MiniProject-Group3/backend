# AI 사용 규칙

AI 도구(Claude Code, Codex, Cursor, ChatGPT 등)를 쓸 때 사람과 AI가 함께 지키는 규칙이에요. 저장소 루트의 `AGENTS.md`·`CLAUDE.md`는 AI 도구가 자동으로 읽는 입구이고, 자세한 내용은 이 문서에 있어요.

## 원칙

**AI는 내용을 쓰고, 실행은 사람이 해요.**

AI가 이슈 본문, 코드, 커밋 메시지, PR 본문, 리뷰 의견의 초안을 써도 돼요. 하지만 저장소와 GitHub에 흔적을 남기는 동작은 사람이 직접 해요. 그래야 누가 무엇을 확인하고 올렸는지가 분명하고, 팀원 모두가 자기 이름으로 올린 코드를 이해하고 있어요.

## 할 수 있는 것과 없는 것

| 단계 | AI가 해도 되는 것 | AI가 하면 안 되는 것 (사람이 함) |
| --- | --- | --- |
| 1. 이슈 | 템플릿에 맞춘 본문 초안 작성 | 이슈 생성·수정·닫기, 라벨·담당자·마일스톤 지정, 댓글 |
| 2. 브랜치 | 규칙에 맞는 이름 제안 | 브랜치 생성·전환·삭제 |
| 3. 작업 | 코드·테스트·설정·문서 파일 작성과 수정, 테스트·빌드 실행, 커밋 메시지 초안 작성 | `git add`, `git commit`, `git push`, `git merge`, `git rebase`, `git reset`, `git stash`, 태그 |
| 4. PR | 제목·본문 초안 작성 | PR 생성·수정·닫기, 리뷰어 지정 |
| 5. 리뷰 | 리뷰어가 요청하면 로컬에서 diff 요약, 문제 후보 찾기 | 리뷰 의견 게시, Approve·Request changes |
| 6. 병합 | — | 병합, 되돌리기(Revert) |

읽기만 하는 명령은 써도 돼요: `git status`, `git diff`, `git log`, `git show`, `git rev-parse --abbrev-ref HEAD`. `git fetch`·`git pull`도 사람이 해요.

## 막는 방법

규칙 문서만으로는 실수를 다 막지 못해서 세 겹으로 막아요.

| 겹 | 내용 | 막는 범위 |
| --- | --- | --- |
| 1. 규칙 문서 | `AGENTS.md`, `CLAUDE.md`, 이 문서 | 모든 AI 도구 (지시로) |
| 2. 도구 설정 | `.claude/settings.json`의 `permissions.deny`로 git 쓰기 명령과 `gh`의 쓰기 명령을 막음 | Claude Code (강제로) |
| 3. 저장소 설정 | `main`·`develop` 브랜치 보호, 승인 1명 필수, 우회 금지 ([CONTRIBUTING.md](CONTRIBUTING.md#저장소-설정-1번7번이-처음에-한-번)) | 모든 도구와 사람 (강제로) |

- Claude Code 외의 도구(Codex, Cursor 등)를 쓰는 사람은 그 도구에서도 git·GitHub 명령을 자동 실행하지 않도록 설정해요(명령마다 확인 받기).
- GitHub MCP 서버나 `gh`를 AI 도구에 연결했다면, 쓰기 권한이 없는 토큰을 쓰거나 쓰기 도구를 꺼요.
- `.claude/settings.json`은 팀 공용이라 함부로 고치지 않아요. 개인 설정은 `.claude/settings.local.json`(커밋 안 됨)에 둬요. 다만 개인 설정으로 deny를 푸는 건 안 돼요.

## AI에게 일을 시킬 때

### 시작 전에 알려 줄 것

- 이슈 번호와 완료 기준
- 담당 서비스 (고쳐도 되는 폴더)
- 고칠 코드 위치 (이 저장소의 서비스 폴더. 원본 코드는 초기 분리 커밋으로 옮겨져 있어요)
- 관련 스펙 ([design.md](design.md)의 장 번호, 내부 API·메시지 번호)

```
#12 작업이야. gateway 폴더만 고쳐.
design.md 4장(인증과 Gateway) 기준으로 JWT 검사 필터를 만들어 줘.
원본에서 옮겨 온 JwtAuthenticationFilter를 참고해.
끝나면 커밋 메시지 초안과 PR 본문 초안을 써 줘.
```

### 원본 저장소를 보여 줘야 할 때

보통은 필요 없어요. 옮겨 온 코드에 없는 원래 모습(지운 코드, 커밋 이력)을 봐야 할 때만, 원본을 [README.md](README.md#원본-코드)대로 저장소 밖에 받아 읽기 범위에 더해 줘요.

```bash
# Claude Code: 이 저장소 루트에서
claude --add-dir <원본을 받은 경로>
```

- 원본은 **읽기만** 해요. 원본 저장소의 파일을 고치지 않아요.
- 원본 파일을 이 저장소로 새로 복사해 오지 않아요. 이 저장소에 옮겨진 코드를 [code-convention.md](code-convention.md)에 맞춰 고쳐요.

### AI가 지킬 것

- **담당 서비스 폴더 밖을 고치지 않아요.** 꼭 필요하면 고치기 전에 사람에게 묻고, PR 본문 초안의 메모에 적어요.
- **스펙을 추측하지 않아요.** 내부 API·토픽·포트는 [design.md](design.md)에서, 외부 API와 원본 테이블은 [reference/](reference/api-spec.md)에서 찾아요. 없으면 만들지 말고 "확인 필요"로 남겨요.
- **진행 상태를 문서로 만들지 않아요.** 작업 현황은 이슈와 PR에 있어요. 상태 정리 파일(TODO.md, 진행상황.md 등)을 만들지 않아요.
- **스펙과 다르게 만들어야 하면 멈추고 알려요.** 스펙 변경 이슈 초안을 써 주는 것까지가 AI의 일이에요.
- **실행 확인 없이 "완료"라고 하지 않아요.** 테스트나 빌드를 돌렸으면 결과를 그대로, 못 돌렸으면 못 돌렸다고 말해요.
- **비밀 값을 읽거나 쓰지 않아요.** `.env`, `*.pem`, 키가 든 파일은 열지 않아요. 예시가 필요하면 `.env.example`을 써요.
- **범위 밖 기능을 만들지 않아요.** V1 작업 중에 V2 기능(재시도, DLT 등)이나 요청하지 않은 리팩터링을 끼워 넣지 않아요.
- 판단이 갈린 곳, 확신이 없는 곳을 PR 본문 초안의 메모에 `(확인 요망)`으로 적어요.

### 사람이 할 것

- AI가 쓴 코드는 **커밋하기 전에 diff를 직접 읽어요.** 설명할 수 없는 코드는 커밋하지 않아요.
- AI가 쓴 이슈·PR 본문은 사실과 맞는지 확인한 뒤 올려요. 특히 "확인 방법"과 "테스트 결과"는 직접 돌려 본 결과여야 해요.
- PR 본문의 메모에 AI에게 무엇을 시켰는지 한 줄 적어요. 예) `JWT 필터 초안과 테스트를 Claude Code로 작성 후 수정`
- 커밋에 AI 공동 작성자 표기(`Co-Authored-By`)는 넣지 않아요. 커밋은 확인하고 올린 사람의 것이에요.

## 초안 형식

AI가 초안을 쓸 때 따르는 형식이에요.

| 초안 | 형식 |
| --- | --- |
| 이슈 | `.github/ISSUE_TEMPLATE/`의 해당 템플릿 항목 순서대로 |
| 브랜치 이름 | `<타입>/<이슈번호>-<서비스>-<짧은-설명>` |
| 커밋 메시지 | `<타입>(<범위>): <제목>` + 본문 + `Refs: #번호` |
| PR | `.github/pull_request_template.md` 항목 순서대로, [CONTRIBUTING.md](CONTRIBUTING.md#pr-본문-쓰는-법)의 문체 |
| 리뷰 의견 | `[필수]` · `[제안]` · `[질문]` 머리말, 파일과 줄 번호 |

초안은 대화창이나 `.ai-drafts/` 폴더(커밋 안 됨)에 써요. 저장소의 다른 위치에 초안 파일을 만들지 않아요.
